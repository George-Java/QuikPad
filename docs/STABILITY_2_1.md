# Liquid Ink 2.1：长文档稳定性修复

## 结论与证据边界

2026-10-28，根据“查看或编辑较多 Markdown，滚动几次闪退”的反馈排查。
确认了 2.0 中无上限的单块文本布局、整篇源码输入、大表格同步构建，以及图片原尺寸解码路径。
这些路径会使布局和内存开销随内容增长，是本次修复对象。

**尚未取得反馈手机的 logcat / Android 历史退出记录，不能将其进程退出原因定论为 OOM 或 GPU 崩溃。**
当前没有 ADB 手机连接；本机模拟器无加速驱动，软件模拟启动也以退出码 1 结束。
下述自动化验证运行于 Flutter 测试引擎，不等于物理设备验收。

## 复现与修复

在 `flutter_app/` 执行：

```powershell
..\.tooling\flutter-sdk\flutter\bin\flutter.bat test test/large_document_test.dart --reporter expanded
```

修复前的四项压力断言全部失败，日志保存在 `.tooling/large-document-before.log`：

| 场景 | 修复前观测 | 2.1 实现 |
| --- | --- | --- |
| 12000 行代码围栏 | 单个 RenderParagraph 接收 228889 字符 | 每片最多 2048 UTF-16 单元 / 32 行，惰性渲染 |
| 单行中文与 Emoji | 单个文本布局接收 120000 UTF-16 单元 | 分片且不切断代理对、CRLF |
| 1000 行双列表格 | 首屏构建 603 个 RichText，并丢掉第 300 行以后显示 | 小批量行分片，首屏控件数量受限，保留所有行 |
| 1400 行源码 | 单个 TextField 接收 126289 字符 | 大文件分段编辑，普通输入段不超过 8192 UTF-16 单元 |

这些断言捕获的是资源开销失控；测试引擎本身未出现进程闪退。
新增图片回归使用真实 2400×2400 PNG 验证解码结果，限制到最多 1536×1024；图片缓存设为 32 MiB / 64 项。

`markdown/preview_items.dart` 保留“显示片段 → 原始块”映射，目录继续按原始块索引跳转。
复制代码复制完整原始代码块；任务勾选作用于原始源码行。
小表格每片容纳多行，大表格和超长单元格继续分片，超长表头保留为续行。

`widgets/source_editor.dart` 保存整篇控制器，仅将当前片段交给 RenderEditable 和系统输入法。
查找命中其他片段时自动定位；大段粘贴重新分段，保存/导出始终读取完整文档。
文本选择限于当前编辑片段，分片边界上的复杂行内 Markdown 可能按原文呈现。
后台解析串行执行并丢弃过时结果，取消“大文件先同步解析再异步解析”的重复工作。
导入先检查文件大小再读取内容，避免在拒绝超限文件前分配全部字节。

## Android 验收与诊断

安装 `dist/LiquidInk-2.1.0-flutter.apk`，使用原来出问题的文件：

1. 预览连续上下滚动，目录跳到最后一节并返回。
2. 切换源码/实时，编辑首段和末段，保存后重新打开，导出核对全文。
3. 用中文输入法连续输入与粘贴，检查 Emoji 和换行。
4. 切换主题，退出应用重开，核对偏好恢复。
5. 若再次退出，重开后进入设置 → 导出诊断报告。

报告仅写到用户选择的位置，不上传，不记录正文。Android 11+ 提供历史退出原因码及 PSS/RSS；应用同时保留有上限的 Flutter 错误类型与堆栈。系统记录可能因机型、版本或记录轮换而缺失。
重点区分 `3=LOW_MEMORY`、`4=CRASH`、`5=CRASH_NATIVE`、`6=ANR`，再决定后续设备专项修复。
